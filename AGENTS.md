# INSIGHT

ALS (amyotrophic lateral sclerosis) voice screening support research prototype: Next.js UI + FastAPI HuBERT inference (`src/backend/`) + Firebase Realtime Database. Uses anonymized/test data only; outputs are screening support, never a diagnosis.

- The original Google Stitch mockups in `design/stitch-mockups/` (`insight_*/code.html`, `screen.png`, `clinical_diagnostic_precision/DESIGN.md`) are the initial visual reference only; nothing imports them at runtime. Keep them unchanged. App code lives in `src/`; the training notebook is `notebooks/HuBERT_Frozen_CNN_Pooling_Reproduction.ipynb`.
- Input is an uploaded audio file. Do not add in-app microphone recording, audio device, sensor, Bluetooth, serial, or hardware features.
- No fictional patient or analysis fixtures in app code. Never fabricate unmeasured values: Jitter/Shimmer/HNR are measured with Praat (`praat-parselmouth`, `src/backend/acoustics.py`) only on sustained-vowel tasks and are `null` with a reason otherwise; status thresholds (`src/backend/interpretation.py`) stay `null` until validated.
- The inference server requires `Authorization: Bearer $INSIGHT_BACKEND_TOKEN` on every route except `GET /health`; without the token it fails closed (503) unless `INSIGHT_ALLOW_UNAUTHENTICATED=1` is set for local development. The Next.js server (`src/app/api/analyze/route.ts`) sends the token.
- An OOD gate (`src/backend/model.py`) withholds the status for inputs outside the training feature distribution; its threshold lives in `ood_calibration.json`, generated by `scripts/calibrate_ood.py` (keep `--check` passing).
- Pages use the async service layer through the shared provider (`src/components/clinical-data-provider.tsx`).
- Firebase: rules deny all client access; only the Next.js server accesses the DB with credentials from `.env.local` (never commit them). Schema: `docs/database-schema.md`.
- Model weights (`head.pt`, `scaler.npz`) are tied to training run 20261005T055211_070474Z by `model_card.json`; regenerate with `scripts/build_model_card.py` after any change and keep `--check` passing.
- VHI-30 items and F/P/E domains in `src/data/vhi.ts` must match the PhenX worksheet; scores are recomputed on the server.
- Validate with `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `python -m unittest discover -s tests/python`, `python scripts/build_model_card.py --check`, `python scripts/calibrate_ood.py --check`, and `python scripts/reproduce_inference.py` (the same steps as `.github/workflows/ci.yml`).
